# Jail executor integration (paired agent-jail migration candidate)

Jail lifecycle belongs to [agent-jail](https://github.com/ryanmaclean/agent-jail). Its bin/jail-execute.nu is the canonical implementation of FreeBSD jail creation, hardening, command execution, timeout and teardown. smolfire owns only executor selection, request identity, network authorization, and the coordinator mailbox reply. The smolfire adapter is bin/coord-jail-dispatch.nu; coord-tick.nu launches its dispatch entry point when a request explicitly selects jail or SMOLFIRE_EXECUTOR=jail on FreeBSD. The default remains vm.

The adapter requires an installed **absolute path** in AGENT_JAIL_EXECUTOR_PATH and a 64-hex SHA-256 pin in AGENT_JAIL_EXECUTOR_SHA256. It verifies the installed script bytes, calls its contract command, requires agent-jail.executor.contract.v1 and executor schema v1, then calls its run CLI. There is deliberately no default executable, checkout search, download, vendor copy, or fallback to another executor. If either setting is absent or invalid, the selected jail request receives one failure reply. No pinned installation artifact is published by this candidate; operators cannot enable successful jail dispatch from this packet alone.

The request's context_pointers.jail_base, jail_zfs_snapshot, or jail_image selects exactly one rootfs source; existing SMOLFIRE_JAIL_BASE, SMOLFIRE_JAIL_ZFS_SNAPSHOT, and SMOLFIRE_JAIL_IMAGE remain fallback settings. timeout_sec or SMOLFIRE_JAIL_TIMEOUT supplies the task deadline, and SMOLFIRE_JAIL_ROOT selects the jail root. SMOLFIRE_JAIL_ALLOW_UNPATCHED remains an explicit escape hatch. The adapter passes --network only when the original request's tools_required contains Network; the coordinator's capability gate must first allow that tool for the role. Agent-jail itself defaults network off.

The agent-jail run command returns one JSON record with verdict, boot_sec, and outputs (plus optional error/warnings). The adapter validates it even on nonzero exit, then preserves the smolfire mbox reply envelope, In-Reply-To dispatch identity, and the claims result block. It emits a failure reply when the request is missing or the pin, contract, launch, JSON, or result validation fails, provided the spool remains readable and writable. A process crash, indefinitely blocked external command, or failed spool write is outside that guarantee and needs an observed native fault test.

tests/coord-jail-dispatch-test.nu uses a fake Nushell CLI under a temporary directory. It tests pin refusal, contract mismatch, result normalization, argv/network forwarding, missing request, and one-reply mbox shape without touching a FreeBSD jail or ZFS dataset. Existing tests/run-all.sh discovers it by the tests/*-test.nu glob. The canonical lifecycle fixtures move to agent-jail; this test is only for smolfire's adapter. Native acceptance must use a disposable off-NAS FreeBSD fixture and the exact pinned artifact, including timeout, teardown, rctl, mac_do, and mailbox failure injection. No live NAS pool is an acceptance target.

This document replaces smolfire's previous lifecycle manual only when the paired deletion and agent-jail PR are reviewed and landed together. It does not claim that transition is complete.
